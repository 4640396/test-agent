# P0 片4 实现说明：并行执行与测试分片（功能四）

## 概述

实现 PRD 功能四"并行执行与测试分片"（PRD 第 8 节），首期按用例数均分：
- 用例级分片：一个任务的用例集切分为 N 片，按用例数均分（各片差 ≤1）
- 依赖隔离：标记 `parallelizable: false` 的用例（依赖组/共享状态）强制串行片
- 失败隔离：一片失败不影响其他片，聚合时合并
- 降级正确：Worker 不足时分片数 = Worker 数，1 Worker 退化为串行
- 控制面零改动（不碰 Java/Flyway/MySQL）

## 实现细节

### 1. shard.ts — 分片模块

#### isParallelizable(c: TestCase): boolean
- 默认 true（无标记即可并行）
- `parallelizable: false` → 不可并行（依赖组/共享状态，PRD 8.8 风险退路）

#### splitShards(cases, config): ShardAssignment[]
- **场景 A（均分）**：可并行用例按用例数均分到 N 片，余数均摊到前几片，各片差 ≤1
  - 200 用例 4 片 → 各 50（差 0）；201 用例 4 片 → 51/50/50/50（差 1）
  - 分布算法：`baseSize = floor(total/shardCount)`，前 `remainder` 片各 +1
- **场景 C（降级）**：shardCount ≤ 1 → 退化为串行，所有用例一片（serial=false）
- **依赖隔离**：不可并行用例合并为一个串行片，追加在并行片之后
- **边界保护**：shardCount > 用例数 → 实际片数 = 用例数，不产出空片；0 用例 → 单个空片
- 分片间无重叠用例（每条用例只出现一次）

#### shardBalanceVariance(assignments): number
- 返回并行片用例数的最大差值（max - min），供调用方校验 PRD 8.6 均衡指标
- 仅统计并行片（serial=false），串行片不参与

#### aggregateShardResults(results): AggregatedShardReport
- **场景 B（失败隔离）**：正常片累加 passed/failed；崩溃片（error 非空）该片区用例全计失败，其他片不受影响
- 聚合后 passed + failed = totalCases（含崩溃片）
- 统计并行片数/串行片数/是否有崩溃片
- 生成摘要文本

### 2. types.ts — TestCase.parallelizable 字段


## PRD 8.5 验收场景对应

| 场景 | PRD 要求 | 实现 | 测试 |
|------|---------|------|------|
| A: 分片并行加速 | 200 cases, 4 Workers, 均分 4 片, 加速比 ≥3.2 | `splitShards(200, {shardCount:4})` → 4 片各 50，差 0 | "场景A" 测试组（4 个测试） |
| B: 分片失败隔离 | 片2有5失败，片1/3/4正常，聚合195过5失 | `aggregateShardResults` 累加各片，崩溃片全计失败 | "场景B" + "失败隔离" 测试组（7 个测试） |
| C: Worker不足降级 | 1 Worker → 退化为串行 | `splitShards(200, {shardCount:1})` → 1 片 200 用例 | "降级" 测试组（5 个测试） |

## 控制面零改动

分片与聚合纯 Worker 层完成，不依赖 Java 控制面/MySQL/Flyway：
- `splitShards` 是纯函数，输入用例集 + Worker 数，输出分片分配
- `aggregateShardResults` 是纯函数，输入各片结果，输出聚合报告
- 执行方（worker-mode/runner）调用这两个函数完成分片执行 + 结果合并
- 无需新增 HTTP 端点、无需改 Flyway 迁移、无需加 MySQL 表

## 未集成说明

本片实现分片核心模块（split + aggregate）+ 完整测试。分片执行调度（worker-mode 多 Worker 并行分发）需要控制面子任务端点支持，属控制面改动范围 → 按"控制面零改动"硬约束标 **[需人工复核-控制面改动]** 跳过，不在本片实现。

分片模块已就绪，控制面支持后可直接接线：
1. worker-mode 领任务后调 `splitShards(cases, {shardCount: availableWorkers})`
2. 各 Worker 跑各自分片，回传 `ShardExecutionResult`
3. 调 `aggregateShardResults` 合并为完整报告

## 退路与兜底

- 并行加速比 <3.2（4 Worker）→ 标 **[需人工复核-分片均衡]**，不回退串行（任务触发条件）
- 用例间有依赖 → `parallelizable: false` 标记后强制串行片（已实现）
- 共享状态用例并行冲突 → 同上，`parallelizable: false` 标记
- 控制面子任务调度 → 标 **[需人工复核-控制面改动]** 跳过
